Quels ports exposer ?

installation reseau

Le fichier compose publie 80 et 443. Puis-je me passer du 80 ? Et le port 8080 ?

Question fréquente · 2026-11-04
Réponse
Réponse de référence
PortOùRôle
443hôteConsole, API et WebSocket, en HTTPS. Indispensable.
80hôteRedirection vers HTTPS, et validation Let's Encrypt si vous l'activez. Facultatif sinon.
8080interneBackend. Ne l'exposez jamais : nginx le sert.
8090interneService de partage de fichiers, sur le réseau files uniquement.

Rien d'autre n'est à ouvrir : terminal SSH, navigateur isolé et partage de fichiers passent tous par le 443, en HTTPS et WebSocket. Le bastion n'a besoin d'aucun port entrant pour joindre les cibles : c'est lui qui se connecte à elles.

Se passer du 80

Sans Let's Encrypt intégré, le 80 ne sert qu'à rediriger vers HTTPS : vous pouvez ne pas le publier. Les utilisateurs devront alors taper https:// explicitement.

Changer les ports

Pour éviter les ports privilégiés, ou si 80 et 443 sont déjà pris :

EF_HTTP_PORT=8080
EF_HTTPS_PORT=8443

Le bastion se joint alors par https://hote:8443. Déclarez cette origine, port compris, pour les passkeys :

ENDORIUMFORT_WEBAUTHN_RP_ID=hote.example.com
ENDORIUMFORT_WEBAUTHN_ORIGIN=https://hote.example.com:8443

Derrière un reverse-proxy

Si Caddy, Traefik ou nginx occupe déjà le 443, le proxy joint le bastion sur le réseau interne. Déclarez alors l'adresse du proxy dans ENDORIUMFORT_TRUSTED_PROXIES : sinon, le journal et la limitation de débit voient l'IP du proxy pour tout le monde.

Pare-feu

  • N'exposez pas le bastion à Internet sans nécessité ; sinon, placez-le derrière un VPN ou une liste d'IP autorisées.
  • Côté cibles, n'acceptez SSH et les interfaces d'administration que depuis l'adresse du bastion : sinon, il se contourne.
